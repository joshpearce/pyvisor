# Pyvisor HTTP API (MVP)

All endpoints use JSON.  Pyvisor is served behind the Tailscale sidecar and
listens on its private network only; see the authentication decision in
`architecture.md`.  Versioned routes are stable for the MVP.

## Identifiers

`session_id` must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`.  It is used only
after validation and is never decoded, normalized, or interpreted as a path.
`job_id` is a lowercase canonical UUID generated by the service.  Both invalid
and unknown identifiers are handled without exposing filesystem paths.

## Common response fields

Job responses have this shape (fields whose value is unknown are `null`):

```json
{
  "session_id": "chat_01",
  "job_id": "8d6f1a7c-8efb-4ccf-9c4a-1ae0bf6a625a",
  "status": "completed",
  "command": "python -c 'print(2 + 2)'",
  "started_at": "2026-08-23T12:00:00Z",
  "finished_at": "2026-08-23T12:00:01Z",
  "exit_code": 0,
  "reason": null,
  "stdout": {"text": "4\\n", "truncated": false, "total_bytes": 2, "returned_bytes": 2},
  "stderr": {"text": "", "truncated": false, "total_bytes": 0, "returned_bytes": 0}
}
```

`status` is one of `running`, `completed`, `timed_out`, `cancelled`, or
`runtime_error`. `reason` is `null` unless a terminal lifecycle transition has
a stable reason token: `timeout`, `cancel_requested`, `service_restart`,
`service_shutdown`, `executor_start_failed`, `executor_wait_failed`,
`timeout_termination_failed`, `cancel_termination_failed`, or
`missing_live_executor`. `exit_code` is populated only after a process exit is known.
Output is decoded as UTF-8 with replacement.  The full byte streams remain at
the output paths in the session directory.  For output larger than the configured
cap, `text` contains equal-sized head and tail portions separated by a fixed
marker, `truncated` is `true`, and `total_bytes` reports the file size observed
while serving the response.  A concurrent running job may append additional
bytes after that observation.

Errors use:

```json
{"error": {"code": "busy", "message": "session already has a live job"}}
```

## `GET /healthz`

Returns `200` and `{"status":"ok"}` when the process can serve requests.
It does not claim that the gVisor runtime is usable.  Runtime readiness is
reported in structured logs and later metrics, so a temporary `runsc` failure
does not make an otherwise healthy process disappear from diagnostics.

## `GET /metrics`

Returns process-lifetime lifecycle metrics in Prometheus text format. It reports
terminal-job counts by status, the current live-job count, idle-runtime reaps
and failures, and startup reconciliation counts. Metrics intentionally contain
no session, job, command, container, or image labels. This endpoint is exposed
only on Pyvisor's private service network.

## `POST /v1/sessions/{session_id}/jobs`

Starts a command:

```json
{"command": "python -c 'print(2 + 2)'", "timeout_seconds": 30}
```

`command` is a non-empty UTF-8 string no longer than the configured command
limit.  It is passed to the executor as a shell command (`/bin/bash -lc`) to
match the agent contract.  `timeout_seconds` is optional; absent uses the
configured default, and supplied values must be integral seconds from 1 through
the configured maximum.  stdin is always closed/empty.

The response is `200` if the job completes during the foreground soft cap and
`202` with `status: "running"` otherwise.  A concurrent live job for the same
session returns `409` with error code `busy`.  Invalid input returns `400`;
a failed runtime setup returns `200` with a durable job response whose status is
`runtime_error` and whose reason is `executor_start_failed`. This preserves the
`job_id` needed to inspect the durable record.

## `GET /v1/sessions/{session_id}/jobs/{job_id}`

Returns the current job response with `200`.  A job not belonging to the named
session, an unknown job, or an unknown session returns `404` with `not_found`.
It returns partial output while the status is `running`.

## `POST /v1/sessions/{session_id}/jobs/{job_id}/cancel`

Requests cancellation of the live job's process group.  It returns `200` with
the job response after cancellation has reached a terminal state.  Cancelling a
terminal job is idempotent and returns its existing response.  An unknown job
returns `404`.  Cancellation that cannot be delivered due to a runtime failure
returns `503` or `500` and records a `runtime_error` terminal state once the
executor is no longer reliable.

## Status and HTTP mapping

| Situation | HTTP | Response |
| --- | --- | --- |
| completed foreground job | 200 | job, `completed` |
| still running after soft cap | 202 | job, `running` |
| timeout/cancelled, including via poll | 200 | terminal job |
| live job already in session | 409 | `busy` error |
| malformed body/id/timeout | 400 | validation error |
| unknown session/job | 404 | `not_found` error |
| durable storage failure | 500 | `internal_error` |
